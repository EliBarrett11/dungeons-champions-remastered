## 7. Champion Ability Specification Format

Use this one format to specify every Champion before its kit is implemented. It is a **review sheet**. Each filled sheet maps field by field onto the canonical JSON Schemas (`champion-combat.schema.json`, `ability.schema.json`, `effect.schema.json`). The JSON content is what the engine executes.

### 7.1 Rules for using the format

1. **One sheet per Champion.** Each sheet must be complete before that Champion's kit is implemented.
2. **Status on every field.** Each field states one of APPROVED DESIGN, PROVISIONAL, PROPOSED or UNRESOLVED.
   - Only APPROVED DESIGN and PROVISIONAL values may be executed.
   - A Champion can be implemented only when every field it needs is APPROVED DESIGN or PROVISIONAL.
3. **UNRESOLVED is a valid answer.** Never fill a field with an invented number, effect or timing. Write `UNRESOLVED` and link the question in rulebook 12. A template is not a reason to invent mechanics.
4. **Shared rules are referenced, not restated.** Critical-hit ranges, resource reset and the opening Ultimate are centralised ([03](03-combat-engine.md)). A sheet may only reference these rules; it never redefines them (`COMBAT/ability-authoring-guide.md` §5).
5. **Text and data must agree.** The player-facing text must describe exactly what the data does. `docs/COMBAT/semantic-validation.md` lists the checks.
6. **Every effect needs a registered implementation.** An effect is usable only when it is a registered, implemented effect ID. Free text is not an effect.

### 7.2 Template

```markdown
# <DC-ID> <Name>

| Field | Value | Status | Source / question |
|---|---|---|---|
| Class / Race / Origin | <from roster> | APPROVED DESIGN | D-021 |
| Role | <one of nine> | PROPOSED until reviewed | U-17 |
| Cost rank (1–5) | <n> | PROPOSED | D-021, U-27 |
| Stats (each canonical stat) | <value or UNRESOLVED> | … | U-17 |
| Class Resource | <resource id; generation events and amounts; target> | … | C-006, U-18 |

## Basic Attack
- Description (player-facing):
- Timer: attack speed (thousandths) …
- Targeting: selector / filters / fallback when no target / when target invalid at resolution
- Damage components: [dice NdM±K, scaling stat, ratio (basis points), damage type, can_crit]
- On-hit effects: [registered effect IDs] or none
- Status:

## Passive
- Trigger (activation enum + event) and resolution window:
- Frequency / internal cooldown / once-per-battle:
- Effects (registered IDs, magnitudes, duration, stacking, refresh):
- Recursion guard (can it trigger itself or its own resource?):
- Status:

## Ultimate
- Activation: resource_threshold (target) — plus the opening Ultimate (CMB-15)
- Cast time: none unless explicitly approved (P-011)
- Targeting, damage components, effects:
- Behaviour when the caster or target is invalid at resolution (C-010):
- Status:

## Feats
- Milestone 1: level <n or UNRESOLVED>; options (≥ 2): …
- Milestone 2: level <n or UNRESOLVED>; options (≥ 2): …  (no Multi-Class, D-020)

## Required tests
- One focused test per component (damage numbers, trigger timing, targeting fallback).
- Deterministic replay with the kit enabled.
- Text and data agree (semantic validation).
```

## 9. Required tests

**Existing.**
- `apps/web/test/roster.test.ts`: 135 Champions, 9 per Trait, unique combinations, canonical names, no Multi-Class.
- `champions.test.ts`: prototype stats and fallback.
- `npm run roster:check`.

**Required per Champion kit, when implemented:**
- the tests listed in its sheet (§7.2);
- a check that no Champion with an UNRESOLVED executable field is marked implemented;
- a semantic-validation pass (`docs/COMBAT/semantic-validation.md`).
